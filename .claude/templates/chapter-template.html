Big picture: why C hands you the keys to memory

C gives you direct access to memory. That is the whole bargain: you get speed and control, and in exchange you are responsible for things other languages handle for you. Everything in this module is one half of that bargain or the other.

A pointer is a variable that holds the address of another variable.

How it works

Declaring a pointer

A pointer does not hold a value. It holds the address where a value lives — like a house number rather than the house.

#include <stdio.h>

int main(void) {
    int age = 30;
    int *p = &age;   /* p holds the ADDRESS of age */

    printf("value: %d\n", age);
    printf("value through p: %d\n", *p);
    return 0;
}
$ cc -std=c17 -Wall -Wextra -Werror pointer_basics.c -o pointer_basics
$ ./pointer_basics
value: 30
value through p: 30

A pointer that was never given an address does not point at "nothing" — it points somewhere random. Reading it is undefined behavior, which means the program may crash, may print garbage, or may appear to work. Always set a pointer before you use it.

Dereferencing a pointer

The * in *p is called the dereference operator: "go to the address p holds, and give me the value sitting there." printf above prints two identical numbers — one read directly from age, one read by following p to that same address — because they are the same memory.

Zooming out: from one pointer to everything built on pointers

Pointers are how C lets you reach memory directly, and nearly everything ahead depends on them: strings, dynamic memory, structs passed to functions, and threads sharing data.
