The Story of C

Last chapter you learned what a CPU does, what source code is, and the difference between a compiled language and an interpreted one. C is a compiled language. This chapter tells you where C came from, what problem it was built to solve, and why it spread so far.

The big picture

Before C, moving a program to a different computer often meant rewriting it from scratch. Programs were written in assembly language — instructions written for one exact kind of computer chip, using that chip's own private vocabulary. An assembly program written for one machine would not run on a different one at all.

That was a real problem for the people building operating systems — the software that manages a computer's hardware and lets other programs run on it. Every new computer meant starting the operating system over. C was built to end that. Knowing why explains a lot of what C still looks like today: a language close enough to the hardware to be fast, but written in a way that could move to a new machine without a full rewrite.

C exists because two programmers at Bell Labs needed a language almost as fast as assembly, but able to move to a new computer without starting over.

How it works

In the early 1970s, Ken Thompson and Dennis Ritchie worked at Bell Labs, a research company in the United States. They were building an operating system called Unix. The first version of Unix was written in assembly language for one specific computer, a PDP-7. It worked, but it was stuck on that one machine.

Thompson first tried a simpler language called B, based on an older language named BCPL. B was easier to move between computers than assembly language, but it was too limited for the job — it had no real way to work with different kinds of data, like whole numbers versus single characters. Between 1971 and 1973, Ritchie extended B with those missing features. The result was a new language: C.

The turning point came when Thompson and Ritchie rewrote most of the Unix operating system itself in C, finishing by 1973. This made Unix one of the first operating systems in history whose core was not written in assembly language.

Rewriting an operating system in C did not make it slow. C was designed to compile down to instructions almost as direct and fast as assembly language — the trade C made was giving up assembly's dependence on one exact computer, not giving up speed.

That rewrite is why C and Unix spread together. A computer maker who wanted to run Unix on new hardware no longer needed to rewrite an entire operating system by hand. Someone had to write a new C compiler — a program that turns C source code into instructions a specific computer can run — for that hardware, and most of Unix's own code could then move over with little or no change. Software that can move to a new computer like this is called portable. Universities and companies picked up Unix because it could follow them onto new machines. C rode along, since Unix and the tools that came with it were written in it.

By 1978, Kernighan and Ritchie's book The C Programming Language gave the growing number of C programmers a shared, informal description of the language. Its first example program, a few lines that print the words "hello, world," became the traditional first program every C learner writes — including you, in a later chapter.

#include <stdio.h>

int main(void) {
    printf("hello, world\n");
    return 0;
}

You are not compiling this yet — that starts in chapter 0.4, once your machine is set up. For now, notice how old this exact greeting is. People have been typing some version of it since the early 1970s.

  • Read Dennis Ritchie's own short account of building C, linked below. Look for the part where he describes B's limits — it is the same problem this chapter already described, in the words of the person who solved it.

Zooming out

C spread because it solved a real problem: it let an operating system move between computers without a full rewrite. That same trade-off — close to the hardware, but not glued to one machine — is why C is still under so much of the software you use every day, more than fifty years later.

C did not stay frozen once it spread, though. The next chapter walks through how C changed over time — the versions named C89, C99, C11, C17, and C23 — and explains why this course teaches you C17, the second-newest version, instead of C23, the newest one.
