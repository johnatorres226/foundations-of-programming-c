The big picture

Every piece of software you have ever used — a game, a calculator app, the page you are reading this on — is a program. Before you write a single line of C, it helps to know what a program actually is and what happens when you run one. C sits closer to the machine than most languages you may have heard of, so the ideas in this chapter matter more here than they would somewhere else.

A computer program is a list of exact instructions that tells a computer's CPU what to do, one step at a time.

How it works

The CPU (short for central processing unit) is the chip inside a computer that carries out instructions. It does not understand English, and it does not understand ideas. It only follows one simple instruction after another, extremely fast — millions or billions of them every second.

You do not write those instructions directly. You write source code: the text a programmer types into an editor, using words like if and printf. Source code is readable by a person. The CPU cannot run it as written — the CPU only understands machine code, which is streams of numbers that map to specific electrical operations inside the chip.

Something has to turn your source code into machine code. There are two common ways to do that, and the difference between them is one of the first things that makes C different from languages like Python.

C is a compiled language. A program called a compiler reads your entire source file and translates it into machine code, all at once, before you ever run it. The output is a new file — the program — that the CPU can run directly, without the compiler's help.

Python and JavaScript are interpreted languages. Instead of translating everything up front, another program called an interpreter reads your source code one line at a time and carries out each line immediately. It does this every single time the program runs.

Compiling does not make your code faster on its own — the CPU runs at the same speed either way. What compiling removes is the translation step at run time. A compiled program is already machine code, so it can start immediately. An interpreted program has to be translated line by line, every time, which is why interpreted programs are often slower to run.

Module 0 has no exercise files to check against a test — that starts in Module 1. For now, try this on your own computer. It needs no compiler and no install.

  • Open any plain text file (a .txt file works) in a text editor. This is what source code looks like: readable words and symbols, meant for a person.
  • Now try opening an installed application's program file in that same text editor — do not run it, just open it as text. Most editors will either refuse or show you a wall of strange symbols.
  • That wall of symbols is close to what machine code looks like when a program meant for a person tries to display it: numbers, not words. That is what the CPU actually reads.

Zooming out

You now know what a program is, and why C needs a compiler to turn your source code into something the CPU can run. That one fact — C is compiled, not interpreted — explains a lot of what makes C feel different from other languages you may have tried.
