Homework: Choosing Many Paths

You've learned how switch picks one path out of several exact values, how fall-through works whether you meant it or not, and what break and continue each actually control. Now put it into practice: four small functions, written from scratch in exercises/ and checked with make check-mine — not by reading this page.

exercises/01_days_in_month.c

Write a function int days_in_month(int month, int is_leap_year) that returns how many days a given month has. Month 1 is January, month 12 is December. Any number outside 1–12 should return 0 — there is no such month.

The chapter's "Grouping cases on purpose" section showed seven months sharing one return 31; by stacking empty case labels. Work out which months share 31, which share 30, and which month needs its own separate case entirely.

February is not like the others — its answer depends on is_leap_year, not on a fixed number. Give it its own case, not a shared one.

exercises/02_bonus_points.c

Write a function int bonus_points(int level) for a three-tier membership. Level 1 is worth 10 points. Level 2 is worth 50 points plus everything level 1 gets. Level 3 is worth 100 points plus everything level 2 gets (which already includes level 1's points). Any other number is not a real level and should return 0.

The chapter's "Falling through on purpose, with code in between" section built exactly this kind of "higher tier includes the lower tiers" logic with deliberate fall-through. Prove to yourself which direction the cases need to be written in for the accumulation to land correctly, and mark each intentional fall-through the way the chapter did.

It is easy to write the cases in the wrong order out of habit — low number first, high number last, the way you would read a table. For the fall-through to accumulate correctly, the highest level's case has to come first in the switch, falling down into the lower ones underneath it.

exercises/03_sum_until_negative.c

Write a function int sum_until_negative(const int *values, int n) that adds up the first n numbers in values, but stops the instant it sees a negative one — that number, and everything after it, is never added.

The chapter's "break: leaving the nearest loop or switch" section showed break stopping a for loop the moment a condition is met, not only skipping one pass of it. Work out where inside the loop that check has to sit.

Stuck? Show one approach 
int sum_until_negative(const int *values, int n) {
    int total = 0;

    for (int i = 0; i < n; i++) {
        if (values[i] < 0) {
            break;
        }
        total += values[i];
    }

    return total;
}

This is one approach, not the answer. A while loop with a hand-rolled counter does the same job — the exact loop shape matters less here than putting the break before the number ever gets added.

exercises/04_count_letters.c

Write a function int count_letters(const char *s) that counts how many letters ('a'–'z' or 'A'–'Z') are in a string. Anything that is not a letter — spaces, digits, punctuation — should be skipped, not counted. If the string contains a '#', stop counting entirely right there; nothing after it counts, even if it is a letter.

The chapter's "continue: skipping to the next iteration" section drew the line between skipping one pass (continue) and leaving the loop entirely (break). This exercise needs both, for two different conditions — work out which keyword belongs to which one.

Checking for '#' and checking for "not a letter" are two separate ifs, not one combined condition — a '#' needs break, everything else non-letter needs continue, and mixing the two up gives you a function that either stops too early or never stops at all.
