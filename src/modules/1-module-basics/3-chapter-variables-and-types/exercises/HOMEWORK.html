Homework: Variables and Types

You've learned what int, char, float, and double each hold, what sizeof can and cannot promise about them, and what happens when a value outgrows its fixed size. Now put it into practice: four small functions, written from scratch in exercises/ and checked with make check-mine — not by reading this page.

exercises/01_digit_value.c

Write a function int digit_value(char c) that takes a single digit character — '0' through '9' — and returns the whole number it represents. digit_value('7') should return the int 7, not the character '7'.

The chapter's "Single characters: char" section showed that a char is really a small number underneath, and that ASCII assigns the ten digit characters consecutive values. Work out what one line of arithmetic does with that fact.

The test calls digit_value with single characters like '0' and '9', not with the two-character text "0". Mixing up single quotes and double quotes here gives the compiler a value of a completely different type.

exercises/02_average.c

Write a function double average(int a, int b, int c) that returns the average of three whole numbers, fraction and all. average(1, 2, 2) should return something very close to 1.6666..., not 1 or 2.

The chapter's "Fractional numbers: float and double" section showed that dividing two ints truncates, even when the result lands in a double afterward. Prove to yourself which part of your expression needs to already be floating-point before the division happens.

(a + b + c) / 3 is int division — it truncates before the result is ever stored in your double. The fix is not in where you store the answer; it is in how you write the division itself.

exercises/03_sizeof_facts.c

Write three small functions that report three facts about sizeof: int size_of_char(void) returns what sizeof(char) reports, int int_is_at_least_two_bytes(void) returns whether sizeof(int) is 2 or more, and int double_is_at_least_as_wide_as_float(void) returns whether double is at least as wide as float.

The chapter's "Asking sizeof" section drew a line between what the C standard actually guarantees about these types and what today's hardware happens to give you. Write each function so it answers honestly, using sizeof directly rather than a number you typed in by hand.

sizeof reports a size_t, an unsigned type — comparing it with >= against a plain number works fine here, but watch the chapter's gotcha on comparing size_t to a negative number later on. It is not a problem in this exercise, but it is worth recognizing the shape of it now.

exercises/04_wrap_add.c

Write a function unsigned char wrap_add(unsigned char a, unsigned char b) that adds two unsigned char values and lets the result wrap around when it goes past what one byte can hold. wrap_add(255, 1) should return 0, not 256 — a single byte cannot hold 256 at all.

The chapter's "Why fixed sizes matter" section showed this exact wraparound with the odometer analogy. Work out the plain arithmetic and casting that reproduces it — no special wraparound function exists in C, because the fixed-width types already behave this way on their own.

Stuck? Show one approach 
unsigned char wrap_add(unsigned char a, unsigned char b) {
    return (unsigned char) (a + b);
}

This is one approach, not the answer. a + b is computed as an int first — C promotes small integer types before arithmetic — so the explicit cast back to unsigned char is what actually produces the wraparound; without it, the compiler warns that you are narrowing an int back down.
