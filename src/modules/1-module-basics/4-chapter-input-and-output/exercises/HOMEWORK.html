Homework: Getting Input and Showing Output

You've learned how printf's format specifiers control what prints and how it lines up, and how scanf reads values back in — including the traps that come with it. Now put it into practice: four small pieces of code, written from scratch in exercises/ and checked with make check-mine — not by reading this page.

exercises/01_format_price.c

Write a function format_price that takes a whole number of cents and writes it into a buffer as a dollar amount — 305 becomes "$3.05", and 5 becomes "$0.05", never "$0.5".

The chapter's field width and precision subsection showed you the specifier that always shows two digits, even for a small remainder — work out which one, and how the whole dollar amount splits into two pieces to begin with.

cents % 100 gives you the remainder, but printing it with a plain %d drops the leading zero on small remainders — 5 instead of 05. That is exactly the trap this exercise is checking for.

exercises/02_format_row.c

Write a function format_row that takes a name and a whole-number score and writes one line into a buffer: the name left-aligned in a 10-character field, followed immediately by the score right-aligned in a 5-character field, followed by a newline.

This is the receipt-style formatting from "Field width and precision" — prove to yourself that a name exactly 10 characters long gets no extra padding, and a name longer than 10 characters isn't cut short.

Stuck? Show one approach 
void format_row(char out[64], char name[], int score) {
    snprintf(out, 64, "%-10s%5d\n", name, score);
}

This is one approach, not the answer. Any format string that left-aligns the name to width 10 and right-aligns the score to width 5 passes — the exact flags you use to get there don't have to match this example.

exercises/03_sum_two_numbers.c

Write a complete program that reads two whole numbers with scanf and prints their sum as Sum: <total>, followed by a newline.

The chapter's "Why scanf skips blanks" subsection showed that %d does not care whether the two numbers are separated by a space or a newline — prove it to yourself by testing both ways at a real terminal before you trust the test alone.

Check scanf's return value before you trust what it read — see "Reading input with scanf" for why a failed read otherwise leaves your variables holding whatever they held before the call.

exercises/04_name_and_age.c

Write a complete program that reads a whole number (an age) with scanf, then reads a full line of text (a name, which may contain a space) with fgets, then prints <name> is <age> years old., followed by a newline.

There's a trap here, and the chapter names it directly: "The trap: a leftover newline breaks the next read". Work out what's still sitting in the input right after scanf("%d", ...) returns, and what you need to do about it before fgets ever runs.

If your program prints an empty name instead of the real one, you skipped the leftover '\n' — the chapter's diagram of the input buffer shows exactly where it sits and why fgets finds it first.

Check all four with make check-mine. To check only this chapter, run make check-mine CHAPTER=1-module-basics/4-chapter-input-and-output.
