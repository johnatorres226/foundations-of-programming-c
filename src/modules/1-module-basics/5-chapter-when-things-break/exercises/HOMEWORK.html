Homework: When Things Break

You've read a compiler error, watched a breakpoint catch a wrong loop bound, and read an AddressSanitizer report catch a buffer overflow. Now put it into practice: three small programs, written from scratch in exercises/ and checked with make check-mine — not by reading this page.

exercises/01_read_the_error.c

Write a complete program that computes the area of a 4-by-5 rectangle and prints exactly one line: Area: 20.

There's a trap here, and it's on purpose: type your first attempt at the multiplication with a typo in one variable's name, the way the chapter's first example did. Compile it. Read the error the compiler gives you — the file, the line, the column, and its own guess at the fix — before you touch the code again. Only then correct the typo and recompile.

The test compares your output letter for letter, including the newline at the end of the line. Get the numbers right but leave off printf's trailing \n, and the check still fails.

exercises/02_off_by_one.c

Write a program that adds up the numbers 1 through 5 with a for loop and prints exactly one line: Sum: 15.

Write the loop condition as i < 5 first, the way the chapter's sum.c example did, and compile with -g. Run it — you should get Sum: 10, not 15. Before you guess at the fix, set a breakpoint inside the loop and step through it with print i and continue, the same way the chapter did. Watch where i stops. Prove to yourself which number the loop never reaches before you change the condition.

Once you see the loop stop one iteration early, resist changing the loop entirely — the fix here is one character, in the condition that decides when the loop stops. A much larger rewrite usually means the real bug was never found, only worked around.

exercises/03_out_of_bounds.c

Write a program that allocates a 5-slot array of int on the heap with malloc, fills it with 0, 10, 20, 30, 40, prints each value on its own line, then frees it.

Write your fill loop's condition as i <= count first, the way the chapter's scores.c example did, and compile with -fsanitize=address — this course's checker already turns it on for you by default, but run it by hand first so you see the report yourself. Read the line number and the "N bytes after a N-byte region" line before you fix anything. Work out which loop bound is wrong and why, the same way the chapter's example did.

Stuck? Show one approach 
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int count = 5;
    int *scores = malloc((size_t) count * sizeof(int));
    if (scores == NULL) {
        fprintf(stderr, "malloc failed\n");
        return 1;
    }

    for (int i = 0; i < count; i++) {
        scores[i] = i * 10;
    }

    for (int i = 0; i < count; i++) {
        printf("%d\n", scores[i]);
    }

    free(scores);
    return 0;
}

This is one approach, not the answer. Checking malloc's result for NULL before using it is good habit, not a requirement the test checks — the loop bound is the part this exercise is really about.
