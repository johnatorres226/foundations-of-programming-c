Homework: How C Becomes a Program

You've learned that the preprocessor runs before the compiler ever checks a single C rule, swapping #define names for their literal text and keeping only one side of an #if/#else. Now put it into practice: three small functions, written from scratch in exercises/ and checked with make check-mine — not by reading this page.

exercises/01_object_macro.c

Name a constant with #define, then write a function that uses it. Define CRATE_SIDE as 4, and write crate_volume() so it returns CRATE_SIDE * CRATE_SIDE * CRATE_SIDE — the volume of a cube-shaped crate with that side length.

The chapter's "Preprocess" section showed CRATE_SIDE get replaced by a plain number before compiling ever starts — prove it to yourself by running cc -E on your own file once it's written, and checking that CRATE_SIDE is nowhere left in the output.

A macro is not a variable. Do not try to change CRATE_SIDE's value anywhere in your code — there is no memory to change. It is text, swapped in once, before your program is even compiled.

exercises/02_function_macro.c

Write a function-like macro named SQUARE, then use it in two functions: square_of_seven() should return 49, and so should square_of_sum(), which computes SQUARE(3 + 4).

The chapter's "Preprocess" section named the trap: a macro missing its parentheses can give the right answer for one input and the wrong answer for another, because it is pasting in raw text, not evaluating a real expression. Work out where every parenthesis has to go so square_of_sum() survives being handed 3 + 4 instead of a plain number.

Stuck? Show one approach 
#define SQUARE(x) ((x) * (x))

int square_of_seven(void) {
    return SQUARE(7);
}

int square_of_sum(void) {
    return SQUARE(3 + 4);
}

This is one approach, not the answer. Any macro that parenthesizes both the parameter and the whole expression passes — the exact spelling of the macro body doesn't have to match this example, only the shape of the parentheses.

exercises/03_conditional_build.c

Use #if/#else/#endif to write two versions of box_capacity(), guarded by a macro named METRIC_UNITS. With METRIC_UNITS defined as 1, the kept version should return 100.

The chapter's "Preprocess" section showed that the untaken branch of an #if is deleted before the compiler ever reads it — so completely that it does not even need to be valid C. Prove it to yourself: once your test passes, replace the #else branch's body with nonsense (misspelled words, unmatched braces, anything) and recompile. It should still build clean, because the preprocessor throws that text away before any C rule gets checked against it. Put the real code back afterward.

Do not delete the #else branch entirely to "clean it up" — an #if without a matching #endif (or one #endif short) is a preprocessor error the compiler cannot recover from, and it will point at a line far from where you actually made the mistake.

Check all three with make check-mine. To check only this chapter, run make check-mine CHAPTER=1-module-basics/2-chapter-how-c-becomes-a-program.
